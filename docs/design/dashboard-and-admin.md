# ダッシュボード・管理機能 詳細設計書

## 1. 生徒のホーム画面

### 1.1 ログイン直後の表示内容

ログイン直後に表示する情報を**優先度順**に配置する。生徒が最も必要とする情報を最上部に、補足情報を下部に配置する。

**表示優先順位:**

| 優先度 | 要素 | 理由 |
|--------|------|------|
| 1 | 朝テスト開始ボタン（配信時） | 朝テストが最優先アクション |
| 2 | ストリーク表示 | 継続モチベーションの核 |
| 3 | グレード進捗カード | 現在の立ち位置の確認 |
| 4 | 学習レコメンドカード | 次にやるべきことの提示 |
| 5 | 学期目標進捗 | 中長期の進捗確認 |
| 6 | 最近のバッジ | 達成感の演出 |

**状態別の表示分岐:**

```
[朝テスト配信中 & 未受験]
  → 画面上部に大きな「朝テストを受ける」ボタンを表示
  → 他の要素はボタンの下に配置（スクロールで見える）

[朝テスト受験済み（当日）]
  → 「今日の結果」カードを上部に表示（スコア・正答率・前回比較）
  → その下に通常のダッシュボード

[朝テスト未配信（休日・未配信日）]
  → 通常のダッシュボード表示
  → 自学自習モードへの導線を目立たせる
```

### 1.2 朝テストへの導線

**ワンタップ開始の実現:**

1. ログイン直後、未受験の朝テストがある場合は画面最上部にフルワイドの目立つバナーを表示
2. バナー内に「テストを始める」ボタンを1つだけ配置
3. タップすると確認なしで即座にテスト画面に遷移（カウントダウン3秒 → 開始）
4. プッシュ通知からの遷移もテスト画面に直接到達

```
┌──────────────────────────────────────────┐
│  朝テストが届いています！                    │
│  英単語テスト Week12 ・ 10問 ・ 3分          │
│                                          │
│       [ テストを始める ]  (大きなボタン)      │
│                                          │
│  残り時間: あと 12分                        │
└──────────────────────────────────────────┘
```

### 1.4 自学自習モードへの導線

自学自習モードへは以下の3つの導線を用意する。

1. **レコメンドカード**: ホーム画面のレコメンドカードに「復習を始める」「昇格テストに挑戦」等のボタンを表示。最も自然な導線
2. **下部ナビゲーション/サイドバー**: 「自学自習」タブから常時アクセス可能
3. **テスト結果画面**: 間違えた問題の「復習する」ボタンから直接復習モードへ

自学自習モードのメニュー構成:
```
自学自習
├── 復習モード（間違えた問題を復習）
│   └── 復習すべき問題: 12問
├── 模擬テスト（昇格テスト）
│   └── 挑戦可能: 英単語E13 / 日本語J7
├── フラッシュカード
│   └── 英単語 / 日本語を選択
└── 一問一答（自由練習）
    └── グレード範囲を選択して練習
```

### 2.4 要注意生徒のアラート

アラートは以下の条件で自動生成される。教員ダッシュボードのトップに常に表示。

**アラート条件と重要度:**

| 重要度 | 条件 | アラートメッセージ例 |
|--------|------|----------------------|
| 高 | 3日以上連続で未受験 | 「{生徒名} 3日連続未受験です」 |
| 高 | 正答率が3週連続で低下 | 「{生徒名} 正答率が3週連続低下(78%→62%→42%)」 |
| 高 | 学期中間で目標達成率20%未満 | 「{生徒名} 学期目標の達成率が15%です(面談推奨)」 |
| 中 | ストリークが途切れた | 「{生徒名} ストリーク途切れ(18日→0日)」 |
| 中 | 昇格テスト3回連続不合格 | 「{生徒名} E8昇格テスト3回連続不合格」 |
| 低 | 1週間自学自習の利用なし | 「{生徒名} 自学自習を1週間利用していません」 |

**アラートの表示仕様:**
- 重要度「高」は赤色バッジ、「中」は黄色バッジ、「低」は灰色バッジ
- 各アラートに「確認済み」ボタンを設置（確認後はアラート一覧に移動し、トップからは消える）
- アラートからワンクリックで該当生徒の詳細画面に遷移可能
- 1日1回の要約メールを教員に送信（オプション、オフ可能）

### 2.5 テスト結果のCSVエクスポート

**エクスポート種類:**

| 種類 | 内容 | 対象選択 |
|------|------|----------|
| テスト結果一覧 | 日付・生徒名・スコア・正答率・合否 | テスト単位 / 期間指定 |
| 問題別正答率 | 各問題の正答率・誤答パターン | テスト単位 |
| 生徒別成績サマリー | グレード・累計正答数・ストリーク・目標進捗 | クラス単位 / 学年単位 |
| 学期末レポートデータ | 学期を通した全成績データ | クラス単位 |

**CSV出力画面:**
```
データエクスポート

対象: [クラス選択 ▼]  [期間: 開始日〜終了日]
種類: ○テスト結果一覧  ○問題別正答率  ○生徒別サマリー  ○学期末レポート

[プレビュー]  [CSVダウンロード]
```

- プレビューで出力内容を10行まで確認可能
- ファイル名は自動生成: `{クラス名}_{種類}_{期間}.csv`
- 文字コードはUTF-8（BOM付き、Excel対応）

## 3. 学校管理機能

### 3.1 管理者の権限設計

**ロール定義（4段階）:**

| ロール | 対象者 | 権限 |
|--------|--------|------|
| **システム管理者** | 教務主任 / ICT担当（1〜2名） | 全権限。年度更新・教員アカウント管理・学校設定 |
| **教科主任** | 英語科主任 / 国語科主任（各1名） | 教科の問題バンク管理・学年目標設定・教科横断の分析閲覧 |
| **担任教員** | クラス担任（約30名） | 担当クラスの成績閲覧・テスト配信・生徒データ閲覧・アラート確認 |
| **教科担当教員** | 教科担当（約30名） | 担当クラスへのテスト配信・問題作成・成績閲覧 |

**権限マトリクス:**

| 機能 | システム管理者 | 教科主任 | 担任教員 | 教科担当教員 |
|------|:-:|:-:|:-:|:-:|
| 教員アカウント管理 | o | - | - | - |
| クラス編成・生徒管理 | o | - | - | - |
| 学校カレンダー管理 | o | - | - | - |
| 年度更新の実行 | o | - | - | - |
| 学年目標グレードの設定 | o | o | - | - |
| 全学年の分析閲覧 | o | o | - | - |
| 問題バンクの全体管理 | o | o | - | - |
| 担当クラスの成績閲覧 | o | o | o | o |
| テスト作成・配信 | o | o | o | o |
| 問題の作成・編集 | o | o | o | o |
| 生徒個別データの閲覧 | o | o | o(担当のみ) | o(担当のみ) |
| 要注意アラートの確認 | o | o | o(担当のみ) | o(担当のみ) |
| CSVエクスポート | o | o | o(担当のみ) | o(担当のみ) |
| 個別生徒の条件調整 | o | o | o(担当のみ) | - |

**ロール付与の運用:**
- システム管理者が教員アカウント作成時にロールを付与
- 1人の教員に複数ロールの付与が可能（例: 担任教員 + 教科主任）
- 担当クラスの紐づけもシステム管理者が設定（年度初めに一括設定）

**生徒の追加・異動:**

| 操作 | 手順 | 備考 |
|------|------|------|
| 生徒の新規追加 | 個別入力 or CSV一括登録 | Googleアカウントのメールアドレスで紐づけ |
| クラス異動 | 生徒を選択 → 異動先クラスを指定 | グレード・バッジ・ストリーク等は全て引き継ぎ |
| 転入生の登録 | 新規追加と同じ手順 | 初期グレードはE1/J1（教員が手動で調整可能） |
| 転出生の処理 | 「転出」ステータスに変更 | データは保持、表示上は非アクティブ |
| 休学生の処理 | 「休学」ステータスに変更 | ストリークは自動フリーズ、データ保持 |

## 6. 年度更新・運用管理

### 6.1 新年度のクラス替え対応

**年度更新の全体フロー:**

```
[3月中旬] 準備フェーズ
  1. システム管理者が「年度更新準備」を実行
  2. 新年度のクラス編成CSVをインポート
  3. 教員の担当クラスを再設定
  4. 新入生のアカウントを一括登録
  5. プレビュー画面で確認

[4月1日] 切替フェーズ
  6. システム管理者が「年度更新を実行」ボタンを押す
  7. 生徒のクラス所属が新年度に切り替わる
  8. 旧年度のデータはアーカイブされる

[4月第1週] 事後フェーズ
  9. 新年度の学期目標が設定可能になる
  10. 教科主任が学年目標グレードを設定
  11. 生徒に新学期の目標設定を促す通知が配信される
```

**年度更新CSV:**
```csv
新学年,新組,出席番号,生徒ID(またはメールアドレス)
2,A,1,aoki@school.example.com
2,A,2,ishii@school.example.com
1,A,1,newstudent1@school.example.com  ← 新入生
```

**年度更新時の注意点:**
- 年度更新は「プレビュー」→「確認」→「実行」の3ステップ。実行後の取り消しは不可
- 実行前にバックアップが自動作成される
- 年度更新は通常の運用時間外（夜間・休日）に実行を推奨

### 6.2 進級時のデータ引き継ぎ

**引き継ぐデータ:**

| データ | 引き継ぎ | 備考 |
|--------|:--------:|------|
| グレード（英単語・日本語） | o | 現在のグレードをそのまま継続 |
| 累計正答数 | o | リセットしない |
| バッジ | o | 獲得済みバッジは永続 |
| 称号 | o | 解放済み称号は永続 |
| ストリーク（現在値） | リセット | 新年度は0日からスタート |
| ストリーク（最長記録） | o | 歴代記録として保持 |
| フリーズ回数 | リセット | 新学期に3回付与 |
| 復活チャレンジ回数 | リセット | 新学期に2回付与 |
| 学期目標 | リセット | 新学期に新たに設定 |
| 復習リスト（Leitner Box） | o | 復習対象はそのまま引き継ぎ |
| テスト受験履歴 | o | 過去データとして閲覧可能 |
| 教員メモ | o | 新担任にも引き継がれる |

**引き継ぎの設計根拠:**
- グレード・バッジ・累計正答数は「これまでの努力の蓄積」なのでリセットしない
- ストリーク現在値は新年度のフレッシュスタート感を出すためリセット
- フリーズ・復活チャレンジは学期単位のリソースなのでリセット
- 復習リストは学習の継続性を保つため引き継ぎ

### 6.3 卒業生のデータ扱い

**卒業処理のフロー:**

```
[3月] 卒業処理
  1. 3年生のステータスを「卒業」に変更
  2. 学期末レポートを一括生成・保存
  3. 卒業生のデータは「卒業生アーカイブ」に移動
```

**卒業生データの保持ポリシー:**

| データ | 保持期間 | 理由 |
|--------|---------|------|
| 成績データ（グレード・テスト結果） | 卒業後3年間 | 指導要録の保存期間に準拠 |
| 個人情報（氏名・メールアドレス） | 卒業後1年間 | 卒業後の問い合わせ対応 |
| バッジ・称号データ | 成績データと同期間 | 成績の一部として扱う |
| 教員メモ | 卒業後1年間 | 引き継ぎ対応 |

**卒業後のアクセス:**
- 卒業生のGoogleアカウントでのログインは卒業年度の3月31日で無効化
- 教員は卒業生アーカイブから過去の成績データを閲覧可能（読み取り専用）
- 保持期間経過後はバッチ処理で自動削除（削除前にシステム管理者に確認通知）

### 6.4 転入・転出生徒の対応

**転入生:**

| 手順 | 操作 | 備考 |
|------|------|------|
| 1 | Googleアカウント発行（学校のIT管理） | システム外の作業 |
| 2 | システム管理者が生徒を登録 | クラス・出席番号を設定 |
| 3 | 初期グレードの設定 | デフォルトはE1/J1。担任が手動で調整可能 |
| 4 | 初回ログイン | Google認証で自動紐づけ |

**転入生の初期グレード調整:**
- 担任教員が転入生の学力を考慮して初期グレードを手動設定できる
- 例: 2年生の途中で転入 → 前校での学習状況に応じてE10/J5等に設定
- 設定したグレードに応じて昇格条件の累計正答数も調整される

**転出生:**

| 手順 | 操作 | 備考 |
|------|------|------|
| 1 | システム管理者が該当生徒を「転出」ステータスに変更 | |
| 2 | クラスの生徒一覧から非表示になる | |
| 3 | データは保持（成績照会に対応するため） | 保持期間: 転出後1年間 |
| 4 | 必要に応じて成績データをCSV出力 | 転出先への引き継ぎ資料 |

### 7.2 パフォーマンス考慮事項
