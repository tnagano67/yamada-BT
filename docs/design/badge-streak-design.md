# バッジ・ストリーク機能 詳細設計書

## 設計方針

- バッジは「少数精鋭」で価値を維持する（初期リリース10個以内）
- ストリークは「参加するだけでカウント」で心理的負荷を下げる
- 学習が苦手な生徒でも手が届くバッジを必ず含める
- 他者との比較ではなく「過去の自分」との比較を軸にする
- 過度な通知・プレッシャーを避け、ポジティブな表現を徹底する

---

## 1. バッジシステム

### 1.1 初期リリースバッジ（10個）

3カテゴリに分け、取得難易度のバランスを取る。

#### カテゴリA: 継続バッジ（3個）

学習を続けること自体を評価する。グレードや正答率に関係なく取得可能なため、学習が苦手な生徒にも最も手が届きやすい。

| # | バッジ名 | 取得条件 | アイコン | 難易度 |
|---|---------|---------|---------|:------:|
| 1 | **はじめの一歩** | 初めて朝テストを受験する（1回目の受験完了時） | 足跡 | ★ |
| 2 | **ウィークリーマスター** | 授業日7日連続で学習する（ストリーク7日達成） | カレンダーに炎 | ★★ |
| 3 | **マンスリーマスター** | 授業日30日連続で学習する（ストリーク30日達成） | 月桂冠 | ★★★★ |

#### カテゴリB: 実力バッジ（4個）

テスト結果や累計の正答数を評価する。コツコツ続ければ自然に取れる設計。

| # | バッジ名 | 取得条件 | アイコン | 難易度 |
|---|---------|---------|---------|:------:|
| 4 | **パーフェクトデイ** | 朝テストで1回全問正解する（10問中10問） | 金の星 | ★★ |
| 5 | **100問の壁突破** | 累計正答数が100問に到達（教科合算） | 数字100のメダル | ★★ |
| 6 | **500問の壁突破** | 累計正答数が500問に到達（教科合算） | 数字500のメダル | ★★★ |
| 7 | **1000問の壁突破** | 累計正答数が1000問に到達（教科合算） | 数字1000のメダル | ★★★★ |

#### カテゴリC: 成長バッジ（3個）

伸びや克服を評価する。結果の絶対値ではなく「成長の過程」を認めるバッジ。

| # | バッジ名 | 取得条件 | アイコン | 難易度 |
|---|---------|---------|---------|:------:|
| 8 | **リベンジ成功** | 過去に不正解だった問題を3問正解する（同一セッション内でなくてよい、累計カウント） | リサイクル矢印 | ★★ |
| 9 | **昇格テスト一発合格** | いずれかのグレードの昇格条件（3回連続80%以上）を、途中で一度も不合格を挟まずに達成する | 稲妻 | ★★★ |
| 10 | **苦手克服** | 過去30問の正答率が40%以下だった教科で、直近30問の正答率が75%以上になる | 山頂の旗 | ★★★★ |

### 1.2 バッジ設計の根拠

**なぜ10個なのか:**
- 高校生にとって「全部集めたい」と思える数が10個前後（多すぎると無関心、少なすぎると物足りない）
- 1学期（約60授業日）で平均的な生徒が5〜7個取得できるペース
- 残りの3〜5個が「次の学期の目標」となり、長期的なモチベーションになる

**難易度分布:**
- ★（誰でも取れる）: 1個 -- 初日に全員が獲得し、バッジシステムの楽しさを体験
- ★★（1〜2週間で取れる）: 3個 -- 早い段階で成功体験を積む
- ★★★（1〜2ヶ月で取れる）: 2個 -- 中期的な目標
- ★★★★（1学期以上かかる）: 4個 -- 長期的な挑戦目標

**意図的に除外したもの:**
- ソーシャルバッジ（「クラスの柱」「学年トップランナー」等）は初期リリースには含めない。競争を煽るリスクがあり、運用が安定してから追加する
- 「ノーミス30」（連続30問正答）は初期には含めない。プレッシャーが強すぎる

| ダブルアップ | 1学期内に2グレード昇格（いずれかの教科） | 成長 | フェーズ2 |

### 1.4 バッジ取得の判定タイミング

| トリガーイベント | 判定するバッジ |
|----------------|--------------|
| 朝テスト提出時 | はじめの一歩、パーフェクトデイ、リベンジ成功、100問/500問/1000問突破 |
| ストリーク更新時（日次バッチ） | ウィークリーマスター、マンスリーマスター |
| グレード昇格時 | 昇格テスト一発合格 |
| 正答率再計算時（日次バッチ） | 苦手克服 |

**判定の実装方針:**
- リアルタイム判定が可能なもの（テスト提出時）は即座に判定・通知
- 集計が必要なもの（ストリーク、正答率推移）は日次バッチ（毎日22:00実行）で判定
- バッジ取得は不可逆（一度取得したら剥奪しない）

  - 500問の壁突破: "ここまで来たあなたはすごい"
  - 1000問の壁突破: "大台突破!伝説の始まり"
  - リベンジ成功: "間違いを力に変えました"
  - 昇格テスト一発合格: "一発クリア!実力の証です"
  - 苦手克服: "苦手を乗り越えました!"
```

## 2. ストリーク設計

### 2.1 1日の学習カウント定義

**基本ルール: 「授業日に朝テストを受験する」= 1日カウント**

| 条件 | カウントされるか | 理由 |
|------|:--------------:|------|
| 朝テストを受験した（正答率不問） | YES | 参加するだけでOK。プレッシャーを最小化 |
| 朝テストで0点だった | YES | 正答率は問わない。受験した事実を評価 |
| 朝テストの締切に間に合わなかった | NO | 15分以内に受験する必要がある |
| 自学自習モードのみ実施（朝テスト未受験） | NO（※例外あり） | 朝テストが主軸。後述の長期休暇ルール参照 |
| 朝テストが配信されなかった日 | 自動スキップ | 教員が配信しなかった日はカウント対象外 |

**例外: 長期休暇中のカウント（後述セクション2.2参照）**

### 2.2 土日・祝日・長期休暇の扱い

#### 学校カレンダー連動

システムは「学校カレンダー」マスタを参照してストリークの対象日を判定する。

```
SchoolCalendar {
  date: Date
  day_type: "school_day" | "weekend" | "holiday" | "vacation" | "exam_period" | "special"
  has_morning_test: boolean    // この日に朝テストが配信されるか
  streak_required: boolean     // ストリーク維持に学習が必要か
  note: string?                // 備考（"体育祭", "中間テスト" 等）
}
```

**カレンダー運用:**
- 年度初めに管理者（教務主任等）が年間カレンダーを一括登録
- CSV形式でのインポートに対応
- 個別の日付を後から修正可能（臨時休校、行事変更等）
- 朝テストの配信スケジュールとカレンダーを連動させる

#### 日種別ごとのストリーク扱い

| 日種別 | ストリーク扱い | 詳細 |
|--------|:------------:|------|
| 授業日（school_day） | カウント対象 | 朝テスト受験でストリーク+1 |
| 土日（weekend） | 自動スキップ | 金曜に受験→月曜に受験で連続扱い |
| 祝日（holiday） | 自動スキップ | 前後の授業日で連続扱い |
| 長期休暇（vacation） | 特別ルール | 下記参照 |
| 定期テスト期間（exam_period） | 自動スキップ | テスト勉強に集中させる |
| 特別日（special） | 設定による | 行事等。管理者が個別設定 |

#### 長期休暇中のストリーク

夏休み・冬休み・春休みは以下のルールを適用する。

```
長期休暇ルール:
  1. 休暇前のストリークは「凍結保存」される
  2. 休暇明けの最初の授業日に朝テストを受験すれば、ストリーク継続
  3. 休暇中に自学自習モードで学習した場合:
     - 「休暇中ボーナス」として記録される（ストリーク本体とは別カウント）
     - 休暇中に5日以上学習した場合、休暇明けのフリーズを+1回追加
  4. 休暇中のストリークカウントは加算しない（不公平防止）
```

**設計根拠:**
- 長期休暇中にストリークを要求すると、家庭環境やネット環境の差で不公平が生じる
- 「凍結保存」により、休暇前の努力が無駄にならない安心感を提供
- 休暇中の自主学習は「ボーナス」として認め、やる気のある生徒を後押しする

### 2.3 ストリークが途切れた時の仕組み

#### フリーズ制度

| 項目 | 仕様 |
|------|------|
| 初期付与数 | 学期開始時に**3回** |
| 自動適用 | 欠席日（授業日に未受験）に自動でフリーズを1回消費 |
| 手動申請 | 不要。欠席した翌日のログイン時に「フリーズが適用されました」と通知 |
| 追加獲得 | ストリーク30日達成ごとに+1回 |
| 公欠対応 | 教師が「公欠」登録した日はフリーズを消費しない（自動判定） |
| 学期繰越 | 未使用フリーズは次学期に繰り越さない（リセット） |
| 上限 | 最大保有数は**5回**（追加獲得しても5を超えない） |

**フリーズ表示:**
```
ストリーク表示例:
  通常日:    🔥 23日連続
  フリーズ日: 🔥 23日連続 (❄️ フリーズ使用)
  フリーズ残: ❄️ x 2
```

#### 復活チャレンジ

ストリークが途切れた場合（フリーズも尽きた状態で未受験）の救済措置。

| 項目 | 仕様 |
|------|------|
| 利用条件 | ストリークが途切れた翌授業日にのみ挑戦可能 |
| 回数制限 | 学期あたり**2回**まで |
| 出題内容 | 直近のグレード範囲から10問（4択形式） |
| 合格条件 | **8問以上正解（80%）** |
| 成功時 | ストリークが途切れる前の日数から継続（「復活」マーク付き） |
| 失敗時 | ストリークは0にリセット。「もう一度始めよう!」のメッセージ |
| 制限 | 途切れてから5日以上経過した場合は復活不可 |

**復活チャレンジの画面フロー:**
```
1. ログイン時に検知:「ストリークが途切れました...」
2. 選択肢を提示:
   a. 「復活チャレンジに挑戦する」（残り回数表示）
   b. 「新しいストリークを始める」
3. a選択 → 10問の4択テスト → 結果表示
   - 合格: 「ストリーク復活! [N]日連続に戻りました!」
   - 不合格: 「惜しかった...でも新しいスタートも素晴らしい!」
```

#### ストリークリセット時のケア

ストリークが0に戻った時、生徒のモチベーション低下を最小限にするための仕組み。

```
リセット時の表示:
  1. 「最長記録」を常にプロフィールに表示
     → "今回のストリーク: 0日 | 最長記録: 45日"
  2. ポジティブなメッセージ
     → "45日も続けた実績は消えません。次の記録に挑戦しましょう!"
  3. 直近のバッジは維持される
     → 「ウィークリーマスター」等、取得済みバッジは剥奪しない
  4. 「再スタートボーナス」
     → リセット後、3日連続で学習すると「再起の炎」通知
```

### 2.4 ストリークリワード

| 連続日数 | リワード | 演出 |
|---------|---------|------|
| 3日 | 「三日坊主突破」通知 | トースト通知 + 炎アイコンがLv.1に |
| 7日 | 「ウィークリーマスター」バッジ | バッジ獲得演出（後述） |
| 14日 | 「2週間達成」通知 + 昇格テスト挑戦回数+1（当日限定） | トースト通知 + 炎がLv.2に |
| 30日 | 「マンスリーマスター」バッジ + フリーズ+1回 | バッジ獲得演出 + フリーズ追加通知 |
| 60日 | 「鉄の意志」バッジ（フェーズ2） + プロフィール炎エフェクト | 特別演出（後述） |
| 100日 | 「不屈のランナー」バッジ（フェーズ2） + 特別称号解放 | 特別演出（後述） |

#### 炎アイコンのレベル

ストリーク日数に応じて、ダッシュボードの炎アイコンが変化する。

```
Lv.0 (0日):     灰色の炎（消えている）
Lv.1 (1〜6日):   小さなオレンジの炎
Lv.2 (7〜29日):  中サイズの赤い炎
Lv.3 (30〜59日): 大きな赤い炎 + 微かなパーティクル
Lv.4 (60〜99日): 青い炎 + パーティクル
Lv.5 (100日〜):  虹色の炎 + 派手なパーティクル
```

この炎レベルは他の生徒からも見える（プロフィール公開設定に関わらず）。直接的な数字の比較ではなく、炎の「見た目」による緩やかな可視化とすることで、過度な競争を避けつつ、「あの炎かっこいい」という動機付けを狙う。

## 3. グレード昇格時の演出

### 3.1 通常グレード昇格（E1→E2、J3→J4 等）

昇格条件（3回連続80%以上）を達成した瞬間に演出を表示する。

```
演出フロー（約5秒間）:
  1. テスト結果画面で「3回連続合格!」のメッセージ（1秒）
  2. 画面が一瞬暗転し、中央にグレード昇格カードが出現（1秒）
     - カードにはグレード名とカラーが表示
     - 例: "E4 ワードスター" （銀のカード）
  3. カードが回転しながら拡大、紙吹雪エフェクト（2秒）
  4. 新しいグレード名と「おめでとう!」メッセージ（1秒）
  5. タップで閉じる → ダッシュボードに反映

画面要素:
  - グレードカード: 新グレードのカラーで縁取り
  - テキスト: "グレードアップ!" (大文字、中央)
  - サブテキスト: "E3 → E4 ワードスター" (グレード名)
  - エフェクト: 紙吹雪（グレードカラーに合わせた色）
  - サウンド: 短い達成音（ファンファーレ系、1秒）
  - ボタン: 「やったね!」（タップで閉じる）
```

### 3.2 復習グレードクリア（E5, E10, E15, E20, E25, E30, E35, E40, E45 / J5, J10, J15, J20）

復習グレードは累計範囲の総復習であり、達成の重みが大きい。通常昇格より一段階豪華な演出とする。

```
演出フロー（約8秒間）:
  1. テスト結果画面で「3回連続合格!」のメッセージ（1秒）
  2. 画面全体にゴールドのオーバーレイ（0.5秒）
  3. 「ブロッククリア!」の大きなテキストが画面上部からスライドイン（1秒）
  4. クリアしたブロックの範囲が表示される（1.5秒）
     - 例: "No.1〜200の200語をマスター!"
  5. グレードカードが豪華版で出現（グレードカラー + 金の縁取り + 輝きエフェクト）（2秒）
  6. 紙吹雪 + 星のパーティクルエフェクト（1秒）
  7. 「次のブロックへ進もう!」のメッセージ + 次のグレード範囲のプレビュー（1秒）
  8. タップで閉じる

追加要素（通常昇格との差分）:
  - ゴールドのオーバーレイ
  - 「ブロッククリア!」テキスト
  - マスター語数の表示
  - グレードカードの金縁取り + 輝き
  - 星のパーティクル
  - サウンド: 通常より豪華なファンファーレ（2秒）
```

### 3.3 完全制覇（E48 / J20）

全グレードをクリアした時の最上位演出。高校3年間の集大成として、特別感を最大限に演出する。

```
演出フロー（約15秒間、スキップ可能）:
  1. テスト結果画面で「3回連続合格!」のメッセージ（1秒）
  2. 画面が暗転（1秒）
  3. 「全 [1900/800] 語 完全制覇」のテキストが一文字ずつ表示（3秒）
  4. 画面全体に虹色のオーバーレイ + 大量の紙吹雪（2秒）
  5. 特別なトロフィーカードが出現（3秒）
     - E48: 「ワードゴッド」ダイヤモンドカード
     - J20: 「ことばマスター」プラチナカード
  6. 「おめでとう! [N]日間の努力が実りました」のメッセージ（2秒）
     - N = 初回朝テストからの日数
  7. 特別称号の解放通知（2秒）
     - E48: 称号「英語の覇者」
     - J20: 称号「国語の達人」
  8. タップで閉じる → プロフィールに特別エフェクト永続付与

特別要素:
  - ダイヤモンド/虹色のカード演出
  - 一文字ずつのテキスト表示
  - 学習開始からの日数表示（達成感の演出）
  - 特別称号の自動付与
  - プロフィールアイコンに永続エフェクト（ダイヤモンドの枠）
  - サウンド: 壮大なファンファーレ（3秒）
```

### 3.4 演出の技術的配慮

| 項目 | 仕様 |
|------|------|
| スキップ | 全ての演出は画面タップでスキップ可能 |
| 再生 | プロフィール画面から過去の昇格演出を再生可能 |
| オフライン | 演出アセットはアプリ初回起動時にキャッシュ |
| パフォーマンス | パーティクル数は端末性能に応じて自動調整（低スペックPCは簡易版） |
| サウンド | デフォルトON、設定で無音化可能 |
| アクセシビリティ | 演出中もスクリーンリーダーで内容を読み上げ |

## 4. モチベーション設計の注意点

### 4.1 学習が苦手な生徒でも楽しめる仕組み

| 施策 | 詳細 |
|------|------|
| **参加だけでストリーク** | 正答率0%でもストリークは加算される。「毎日来る」こと自体を評価 |
| **低ハードルのバッジ** | 「はじめの一歩」は初日に全員獲得。「100問の壁突破」は毎日受験すれば2週間で到達 |
| **成長バッジの存在** | 「リベンジ成功」「苦手克服」は現在の成績が低い生徒ほど取りやすい |
| **スモールステップ表示** | 「あと3問で100問突破!」「あと2日でウィークリーマスター!」と具体的な残りを表示 |
| **取り組み量の評価** | 正答数だけでなく「解いた問題数」もプロフィールに表示 |
| **絶対評価のみ** | 他の生徒との比較は一切しない（クラス平均も個人を特定できない形式） |

### 4.2 過度なプレッシャーにならない工夫

| 施策 | 詳細 |
|------|------|
| **降格なし** | グレードは上がるのみ。「せっかく上がったのに...」というストレスを排除 |
| **フリーズ制度** | 体調不良や忙しい日があっても、3回まではストリークが守られる安心感 |
| **凍結保存** | 長期休暇でストリークがリセットされない安心感 |
| **復活チャレンジ** | ストリークが切れても「まだチャンスがある」という希望 |
| **ポジティブな言葉遣い** | システム全体で「不合格」→「もう少し!」、「失敗」→「次の挑戦へ」に統一 |
| **通知の制限** | プッシュ通知は1日最大2回まで。すべてオフ設定可能 |
| **ストリーク途切れの通知なし** | ストリークが途切れたことをプッシュ通知しない（次回ログイン時に画面上で表示のみ） |
| **最長記録の保存** | ストリークがリセットされても「最長記録」はずっと残る |

### 4.3 他の生徒との比較の扱い

**基本方針: 「自分との比較 > クラスとの比較 > 個人間の比較」**

| レベル | 表示内容 | 公開範囲 |
|--------|---------|---------|
| **自分との比較（推奨）** | 先週の自分との正答率比較、前回テストとの比較グラフ | 本人のみ |
| **クラスとの比較（匿名）** | クラス平均グレード、グレード分布（匿名棒グラフ） | クラス全員 |
| **個人間の比較（制限付き）** | 炎アイコンのレベル（間接的にストリークの長さが分かる） | プロフィール閲覧時 |

**明示的に禁止するもの:**
- 個人の成績ランキング表示
- 「クラスで何位」の表示
- 他の生徒のグレードを一覧表示する機能
- 成績の低い生徒を目立たせる表示

**生徒が自分で選べるもの:**
- バッジの公開/非公開（デフォルト: 公開）
- 称号の公開/非公開（デフォルト: 公開）
- グレードの公開/非公開（デフォルト: 非公開）
- 炎アイコンは常に表示（レベルのみ。具体的な日数は本人のみ）

## 7. バッジ判定ロジック（疑似コード）

```
// 朝テスト提出時に呼ばれる関数
function onQuizSubmitted(studentId, quizResult):
  // はじめの一歩
  if not hasBadge(studentId, "first_step"):
    awardBadge(studentId, "first_step")

  // パーフェクトデイ
  if quizResult.scorePercentage == 100:
    if not hasBadge(studentId, "perfect_day"):
      awardBadge(studentId, "perfect_day")

  // 累計正答数バッジ
  totalCorrect = getTotalCorrectCount(studentId)
  if totalCorrect >= 100 and not hasBadge(studentId, "100_correct"):
    awardBadge(studentId, "100_correct")
  if totalCorrect >= 500 and not hasBadge(studentId, "500_correct"):
    awardBadge(studentId, "500_correct")
  if totalCorrect >= 1000 and not hasBadge(studentId, "1000_correct"):
    awardBadge(studentId, "1000_correct")

  // リベンジ成功
  revengeCount = countRevengedQuestions(studentId, quizResult)
  if revengeCount >= 3 and not hasBadge(studentId, "revenge_success"):
    awardBadge(studentId, "revenge_success")

  // バッジ条件の判明チェック
  checkBadgeReveal(studentId)


// 日次バッチで呼ばれる関数（毎日22:00）
function dailyStreakCheck():
  today = getToday()
  calendarEntry = getSchoolCalendar(today)

  if calendarEntry.day_type != "school_day":
    return  // 授業日以外は何もしない

  for each student in getAllStudents():
    if hasSubmittedQuizToday(student.id, today):
      incrementStreak(student.id)
      checkStreakBadges(student.id)
    else:
      if student.freeze_remaining > 0:
        useFreezeAndLog(student.id, today)
      else if isExcused(student.id, today):
        logExcused(student.id, today)
      else:
        breakStreak(student.id, today)


// ストリークバッジのチェック
function checkStreakBadges(studentId):
  streak = getCurrentStreak(studentId)

  if streak >= 7 and not hasBadge(studentId, "weekly_master"):
    awardBadge(studentId, "weekly_master")
  if streak >= 30 and not hasBadge(studentId, "monthly_master"):
    awardBadge(studentId, "monthly_master")
    addFreeze(studentId, 1)  // フリーズ+1


// グレード昇格時に呼ばれる関数
function onGradePromoted(studentId, gradeId, attemptHistory):
  // 昇格テスト一発合格チェック
  // 3回連続合格の途中で不合格がなかったかを確認
  if attemptHistory.allPassed and not hasBadge(studentId, "first_try_pass"):
    awardBadge(studentId, "first_try_pass")


// 苦手克服チェック（日次バッチ）
function checkWeaknessOvercome(studentId):
  for each subject in ["english", "japanese"]:
    pastAccuracy = getAccuracy(studentId, subject, 60_days_ago, 30_days_ago)
    recentAccuracy = getAccuracy(studentId, subject, 30_days_ago, today)

    if pastAccuracy <= 40 and recentAccuracy >= 75:
      if not hasBadge(studentId, "weakness_overcome"):
        awardBadge(studentId, "weakness_overcome")
