# 朝テスト運用フロー 詳細設計書

## 1. 運用の全体方針

### 1.1 基本コンセプト

朝テストは**教員の負担を最小限にしつつ、全校で継続運用できる**仕組みを目指す。

- 出題は**システムが生徒ごとに自動で行い**、全教員が操作する必要はない
- グレード進行は**システムが自動管理**し、教員は監視・調整のみ
- 朝テストは**生徒の現在グレードに応じて個別のテストが自動配信**される
- 曜日ごとに英語・国語を固定し、ルーティン化する

### 1.2 出題の基本方式: 生徒個別テスト

朝テストでは**生徒ごとに現在のグレード範囲から個別に出題**する。

**理由:**
- 生徒が常に自分のグレードの問題に取り組むため、学習効率が高い
- 朝テストの結果が常にグレード昇格カウントに反映される（グレード不一致の問題が発生しない）
- 教員がグレード範囲を指定する必要がなく、運用負荷が極めて低い
- 問題は単語帳マスタから完全自動生成・自動配信される
- 3回連続80%以上で昇格（朝テストでも自学自習モードでも昇格可能）

**補足:**
- 問題はシャッフルされるため、隣の生徒と全く同じ並びにはならない
- 選択肢もシャッフルされるため、単純な答え写しは防止される
- 先に進みたい生徒は自学自習モードの昇格テストでも自分のペースで昇格可能

## 2. 教員の役割分担

### 2.1 関係者と役割

| 役割 | 対象者 | 人数目安 | 主な業務 |

| **国語科主任**（配信スケジュール管理） | 国語科の主任教員（または教科代表） | 1名 | 配信スケジュール管理（曜日パターン・休止期間設定）、グレード分布確認 |
| **HR担任** | 各クラスの担任 | 約30名 | 朝テスト実施の見守り、結果確認、声かけ |
| **学年主任** | 各学年の主任 | 3名 | 学年全体の進捗監視、HR担任への情報共有 |

| 操作レベル | 人数 | 操作内容 |
|-----------|------|---------|
| **配信スケジュール管理**（学期初め + 必要時） | 2名（教科主任） | 曜日パターン設定、休止期間設定、グレード分布確認 |
| **結果確認**（毎日） | 約30名（HR担任） | ダッシュボードで自クラスの受験状況・成績確認 |

### 2.3 配信スケジュール管理の担当

- 英語科主任・国語科主任（または教科代表）の**2名**が配信スケジュール管理を担当
- 主な業務は学期初めの曜日パターン設定と休止期間設定のみ（日常的な出題操作は不要）
- 教科主任が不在（出張・病欠）の場合、**同教科の別教員が代理**で対応
- 代理操作は権限設定で教科教員がアクセス可能にしておく

## 3. 配信スケジュール管理

### 3.1 出題方式: 生徒個別自動配信

朝テストは**生徒ごとに現在のグレードに応じたテストが自動配信**される。教員がグレード範囲を指定する必要はない。

| 項目 | 内容 |
|------|------|
| **出題範囲** | 各生徒の現在グレード（システムが自動判定） |
| **問題生成** | 単語帳マスタから完全自動生成 |
| **配信** | 配信スケジュールに基づき自動配信 |
| **教員の操作** | 曜日パターンと休止期間の設定のみ |

### 3.2 曜日パターンの設定

教科主任が学期初めに曜日パターンを設定する。

| 曜日パターン例 | 英語 | 国語 |
|--------------|------|------|
| **パターンA（推奨）** | 月・水・金 | 火・木 |
| **パターンB** | 月・水 | 火・木・金 |
| **パターンC** | 月・火・水 | 木・金 |

```
設定画面の流れ:
1. 教科主任が「配信スケジュール」メニューを開く
2. 曜日ごとに教科（英語/国語）を割り当て
   例: 月水金=英語、火木=国語
3. 配信時間を確認（デフォルト: 8:15配信、8:30締切）
4. 休止期間を登録（テスト週、長期休暇等）
5. 「確定」で設定完了
```

### 3.3 休止期間の管理

| 休止期間 | 設定タイミング |
|---------|-------------|
| **定期テスト週** | 学期初めにまとめて登録 |
| **長期休暇** | 学期初めにまとめて登録 |
| **学校行事** | 随時追加 |
| **臨時休止** | 教科主任が随時設定 |

## 4. 朝テストの1日のタイムライン

### 4.1 標準タイムライン

```
前日夜     【自動】システムが翌日の個別テストを生成
           （各生徒の現在グレードに応じた問題を自動生成）

 7:30     【自動】テストデータがサーバーに準備完了

 8:15     【自動】テスト配信 + プッシュ通知
           「今日の英単語テスト（あなたのグレード: E3）が届きました」

 8:20     【HR開始】担任が「テスト開きましょう」と声かけ
           生徒がPCを開き、テスト画面にアクセス
           ※ ログインはGoogleアカウント（通常は既にログイン済み）

 8:20-8:23 【テスト実施】制限時間3分、4択10問
           ※ 問題・選択肢はシャッフル済み

 8:23-8:25 【結果確認】即時に正答率・正答/誤答が表示
           担任: 「グレード昇格した人はいますか？」と声かけ
           生徒: 間違えた問題を30秒確認

 8:25      【HR通常運営へ】連絡事項等
           ※ テスト全体で5分以内に完了

 8:30     【自動】配信から15分後にテスト締切
           未受験者は「未受験」として記録
```

### 4.2 教員の朝のアクション（所要時間: 約1分）

HR担任はテスト作成の操作は不要。朝のアクションは以下のみ:

1. **8:20** - 「テストを始めましょう」と生徒に声かけ
2. **8:23** - ダッシュボードをチラ見し、受験率を確認
3. **8:25** - 「グレード昇格した人はいますか？ おめでとう!」と声かけ
   - ダッシュボードの「本日の要点」に昇格者・正答率等が自動表示されるので読み上げるだけでOK

### 4.3 遅刻者・欠席者の扱い

| 状況 | 対応 |
|------|------|
| **遅刻（締切前に到着）** | 到着後すぐにテストを受験可能。制限時間3分はそのまま適用 |
| **遅刻（締切後に到着）** | 未受験扱い。ストリークはフリーズで救済される可能性あり |
| **欠席** | 未受験扱い。教員が「公欠」登録すればストリーク維持 |
| **デバイス不具合** | 担任が管理画面から「受験延長」を個別に設定可能（+15分まで） |

**未受験のグレード昇格への影響:**
- 未受験日は「連続カウント」を維持（リセットしない）
- ただし加算もされない
- 翌日以降に受験して合格すれば、連続カウントは継続

### 4.4 金曜日の特別運用（週まとめ）

金曜日は「週まとめテスト」として、その週に出題した範囲を復習:

```
月〜木に出題した範囲から出題
  - 月: E4の新出単語 → 金: E4全体の復習テスト
  - その週の間違いが多かった問題を優先的に出題

教員の追加操作は不要:
  - システムが月〜木の正答率データを分析し、自動で復習問題を生成
  - 配信スケジュールに金曜が含まれていれば自動で復習テストが配信される
```

## 5. グレードと朝テストの連動

### 5.1 朝テストと個人グレードの関係

朝テストの出題範囲 = 生徒の現在グレード範囲であるため、**朝テストの結果は常にグレード昇格カウントに反映**される。

| 項目 | 内容 |
|------|------|
| **出題範囲** | 各生徒の現在グレード（システムが自動判定） |
| **昇格判定** | 3回連続80%以上で昇格 |
| **昇格手段** | 朝テストでも自学自習モードでも昇格可能 |
| **グレード不一致** | 発生しない（常に自分のグレードが出題されるため） |

### 5.2 朝テストの結果がグレード昇格に反映される仕組み

```
各生徒に対して、その生徒の現在グレードから出題:

例: 生徒Aの現在グレード = E4 のとき
  → 朝テストでE4の範囲（No.151〜200）から出題
  → 80%以上なら連続カウント+1
  → 3回連続80%以上でE5に昇格
  → 昇格後は翌日からE5の範囲で出題

例: 生徒Bの現在グレード = E2 のとき
  → 朝テストでE2の範囲（No.51〜100）から出題
  → 同様に3回連続80%以上でE3に昇格
```

**先に進みたい生徒は、自学自習モードの昇格テストでも自分のペースで昇格可能。** 朝テストは学習習慣の形成が主目的であり、自学自習モードと合わせて昇格を目指せる。

### 5.3 グレード昇格の判定タイミング

| タイミング | 処理 |
|-----------|------|
| **朝テスト提出直後** | 正答率を判定し、連続カウントを更新 |
| **連続カウントが3に到達** | 即座に昇格処理を実行 |
| **昇格通知** | テスト結果画面に「昇格おめでとう!」を表示 |
| **ダッシュボード反映** | 次回ログイン時にグレードカードが更新される |

昇格は**リアルタイム処理**。朝テストでの昇格も、自学自習モードでの昇格も同じタイミングで反映される。

### 5.4 復習グレード（累計範囲）の朝テストでの扱い

復習グレード（E5, E10, E15等）は、生徒が自動的にそのグレードに到達した時点で出題される。

```
生徒の昇格に伴う自動遷移の例:

E1（No.1〜50）で3回連続80%以上 → E2に昇格
E2（No.51〜100）で3回連続80%以上 → E3に昇格
E3（No.101〜150）で3回連続80%以上 → E4に昇格
E4（No.151〜200）で3回連続80%以上 → E5（復習グレード）に昇格
E5 復習（No.1〜200の累計範囲）で3回連続80%以上 → E6に昇格

※ 各生徒が個別ペースで進行するため、教員による進度管理は不要
※ 復習グレードも他のグレードと同じ昇格条件（3回連続80%以上）
```

## 6. 年間・学期の運用計画

### 6.1 年間スケジュール概要

```
4月  ┌─ 年度開始準備
     │  - システム管理者: 新年度のクラス・生徒データ登録
     │  - 教科主任: 配信スケジュール設定（曜日パターン + 休止期間）
     └─ 新入生: グレードE1/J1からスタート
        進級生: 前年度のグレードを引き継ぎ

4月〜7月 【1学期】
     Week 1   : 学期目標設定期間（生徒が目標を登録）
     Week 2-6 : 通常運用（朝テスト + 自学自習）
     Week 7   : 中間チェックポイント（自動進捗通知）
     Week 8-12: 通常運用
     Week 13  : 期末テスト前（通常通り個別配信を継続）
     Week 14  : 期末テスト週（朝テスト休止）
     Week 15  : 学期末レポート出力 + 次学期の目標検討

7月〜8月 【夏休み】
     - 朝テストは休止
     - 自学自習モードは任意で利用可（ストリークは自動スキップ）
     - 希望者向け「夏休みチャレンジ」（自学自習でグレードアップ）

9月〜12月 【2学期】（1学期と同じ流れ）

12月〜1月 【冬休み】（夏休みと同じ扱い）

1月〜3月 【3学期】
     - 3年生: 受験対策モード（全範囲復習中心）
     - 1-2年生: 通常運用 + 年間目標の最終チェック
     - 年度末: 年間レポート出力
```

### 6.2 学期ごとの設定フロー

```
学期開始2週間前  教科主任が配信スケジュールを設定
                ├─ 曜日パターンの設定（月水金=英語、火木=国語 等）
                ├─ 休止期間の登録（テスト週、長期休暇等）
                └─ 配信時間の確認（デフォルト: 8:15）

学期 Week 1      生徒の目標設定
                ├─ システムが個人ごとの推奨目標を表示
                ├─ 生徒が目標を確認・調整
                └─ HR担任が一覧を確認
                    （特に低すぎる目標の生徒に声かけ）

学期中          教科会議（月1回）でグレード分布を確認・分析
                - 「1年A組のグレード分布: E3が5名、E4が12名、E5以上が15名」
                - 「全体的に順調に進行しています」
                - 特定グレードに停滞している生徒への個別対応を検討
```

### 6.3 定期テスト前後の運用

| 時期 | 朝テストの運用 |
|------|--------------|
| **定期テスト2週間前** | 通常通り個別配信を継続（各生徒が自分のグレードで学習） |
| **定期テスト1週間前** | 通常通り継続。自学自習モードでの昇格テストも一時停止推奨 |
| **定期テスト期間中** | 朝テスト休止（テスト週は配信停止に設定） |
| **定期テスト翌週** | 朝テスト再開（各生徒の現在グレードから自動配信が再開） |

**教科主任の設定操作:**
- 配信スケジュールの「休止期間」にテスト週を登録するだけ（1分で完了）

### 6.4 長期休暇中の運用

| 項目 | 設定 |
|------|------|
| **朝テスト** | 休止（配信停止） |
| **ストリーク** | 自動スキップ（カウント維持、リセットなし） |
| **自学自習モード** | 利用可能（任意） |
| **夏休みチャレンジ** | 希望者向けの特別課題（復習グレード中心） |
| **宿題テスト** | 教員が「休暇課題テスト」として個別配信可能 |

## 7. 教員間の連携

### 7.1 配信状況の共有フロー

出題は完全自動のため、**出題内容の共有フローは不要**。教員間の共有は配信スケジュールと結果データが中心となる。

```
配信スケジュール変更時（教科主任が設定変更した場合のみ）
  │
  ├─ 自動通知: 同教科の教員にメール/アプリ通知
  │   「英語朝テストの配信スケジュールが変更されました（休止期間追加等）」
  │
  └─ 教科チャネル（チャットツール等）に自動投稿
      - 変更内容（曜日パターン変更、休止期間追加等）
```

**出題内容の共有が不要な理由:**
- 問題は単語帳マスタデータから生徒ごとに自動生成されるため、教員の出題操作自体がない
- 問題内容のミスが起きにくい（マスタデータに基づく自動生成）
- 教科主任はダッシュボードで配信状況・結果をいつでも確認可能

### 7.2 成績データの共有範囲

| データ | HR担任 | 同教科教員 | 教科主任 | 学年主任 | 管理者 |
|--------|:------:|:---------:|:--------:|:--------:|:------:|
| 自クラスの個人成績 | o | - | o | o | o |
| 自クラスの統計情報 | o | o | o | o | o |
| 他クラスの個人成績 | - | - | o | o | o |
| 他クラスの統計情報 | - | o | o | o | o |
| 学年全体の統計 | o | o | o | o | o |

- HR担任は自分のクラスの生徒個人データにアクセス可能
- 教科教員は自分が担当する学年の統計情報にアクセス可能
- 教科主任・学年主任・管理者は全データにアクセス可能

### 7.3 権限設計

| ロール | 権限 |
|--------|------|
| **教科主任** | 配信スケジュール管理（曜日パターン・休止期間）、全学年の成績閲覧、グレード分布確認 |
| **教科教員** | 配信スケジュール管理（代理時）、成績閲覧（自学年の統計） |
| **HR担任** | 自クラスの成績閲覧、公欠登録、受験延長設定 |
| **学年主任** | 学年全体の成績閲覧、学期レポート出力 |
| **システム管理者** | 全権限 + アカウント管理 + 年度更新 + マスタデータ管理 |

## 8. 配信スケジュールの設定手順

### 8.1 日常の操作

**出題はシステムが完全自動で行うため、日常的な出題設定操作は不要。**

教科主任が行うのは以下の場合のみ:
- 臨時の休止期間追加（学校行事等）
- 曜日パターンの変更（学期途中で変更が必要な場合）

### 8.2 学期初めの一括設定（教科主任の操作、所要時間: 約10分/学期）

学期開始時に、配信スケジュールを設定する。

```
Step 1: ログイン → 「配信スケジュール管理」メニュー

Step 2: 学期の基本情報を入力
  - 学期: 2026年度 1学期
  - 開始日: 4/8（月）
  - 終了日: 7/18（金）

Step 3: 曜日パターンの設定
  - 英語: 月・水・金
  - 国語: 火・木
  ※ 各曜日の問題形式は自動設定（4択10問がデフォルト）

Step 4: 休止期間の登録
  - 期末テスト週: 7/7〜7/11
  - その他の休止日があれば追加

Step 5: 配信時間の確認
  - 配信: 8:15
  - 締切: 8:30（配信15分後）

Step 6: 「確定」で設定完了
  → 各日の個別テストはシステムが前日夜に自動生成
  → 途中で休止期間を追加したい場合は随時変更可能
```

※ グレード範囲の指定や週ごとの出題計画は不要（各生徒の現在グレードに応じてシステムが自動出題）

## 9. 問題の自動生成ルール

### 9.1 4択問題の自動生成

朝テストの4択問題は、教員が手動作成する必要はない。単語帳マスタデータから自動生成される。

```
入力: 各生徒の現在グレード（システムが自動判定。例: E4 = No.151〜200の50語）
出力: 4択10問

生成ロジック:
1. グレード範囲から10語をランダムに選出（出題語）
2. 各出題語に対して:
   a. 正解選択肢 = その語の意味
   b. 誤答選択肢 = 同グレード範囲内の他の語の意味からランダムに3つ選出
   c. 選択肢の順序をシャッフル
3. 問題の順序をシャッフル

復習グレード（E5等）の場合:
  - 累計範囲からまんべんなく出題（各ブロックから均等に抽出）
  - 過去に間違えた語を優先的に出題（最大30%まで）
```

### 9.2 記述式問題の自動生成

```
入力: 各生徒の現在グレード（システムが自動判定） + 出題方向（英→和 or 和→英）
出力: 記述8〜10問

生成ロジック:
1. グレード範囲から8〜10語をランダムに選出
2. 英→和: 英単語を提示 → 日本語の意味を記述
3. 和→英: 日本語の意味を提示 → 英単語を記述
4. 許容パターンは単語帳マスタに事前登録済み
```

### 9.3 教員による問題のカスタマイズ

自動生成された問題は配信前にプレビュー可能。以下の操作ができる:

- 特定の問題を差し替え（別の語に変更）
- 選択肢を手動で調整
- 問題数の増減（8〜12問の範囲で）
- 手動で作成した問題を追加

**通常運用では自動生成のまま配信すればよく、カスタマイズは任意。**

## 10. 異常系・トラブル対応

### 10.1 想定されるトラブルと対応

| トラブル | 対応 |
|---------|------|
| **Wi-Fi接続不良** | オフライン受験モード（テスト開始時にデータをキャッシュ。提出はオンライン復帰後に自動送信） |
| **配信忘れ** | 配信スケジュールが設定されていれば自動配信のため原則発生しない。スケジュール未設定の場合は教科主任にアラート通知 |
| **全員のPC起動が遅い** | HR担任が管理画面から「締切延長」（+10分まで）を実行 |
| **特定生徒のPC故障** | 担任のPCまたはスマホで受験可能（Googleアカウントでログイン） |
| **出題内容の問題** | 自動生成のため出題ミスは原則発生しない。万一問題がある場合は教科主任権限で「テスト無効化」が可能 |

### 10.2 配信忘れ防止の仕組み

- 配信スケジュールが設定されていれば、テストは完全自動生成・自動配信のため配信忘れは原理的に発生しない
- 学期初めに配信スケジュールを設定し忘れた場合に備え、配信スケジュール未設定の教科がある場合は教科主任にアラート通知
- 緊急時は教科主任が「本日の配信を追加」ボタンで即時対応可能（30秒で完了）

## 11. 導入・移行計画

### 11.1 段階的な導入ステップ

```
Phase 1: 準備（導入1ヶ月前）
  - システム管理者がアカウント・クラスデータを登録
  - 教科主任が年間計画を策定
  - 教科主任に配信スケジュール設定の研修（30分程度）

Phase 2: 教員トライアル（導入2週間前）
  - 教科主任が配信スケジュール設定の練習（テストクラスを使用）
  - HR担任がダッシュボードの確認方法を練習
  - 不明点の洗い出し・FAQ作成

Phase 3: 生徒トライアル（導入1週間前）
  - 1〜2クラスで試験運用
  - 生徒のPC操作（ログイン・テスト受験）を確認
  - 問題点の修正

Phase 4: 全校運用開始
  - 最初の2週間は「お試し期間」（成績はグレードに反映するが、問題があれば調整）
  - 2週間後に教科会議でフィードバック収集
  - 必要に応じて運用ルールを微調整
```

### 11.2 教員向け研修内容

| 対象 | 内容 | 所要時間 |
|------|------|---------|
| **教科主任** | 配信スケジュール設定・グレード分布確認・レポート出力 | 30分 |
| **HR担任** | ダッシュボードの見方・公欠登録・声かけのポイント | 30分 |
| **全教員** | システム概要・生徒への説明方法 | 15分（全体会） |

## 12. 運用負荷のまとめ

### 教員ごとの週間作業時間の見積もり

| 役割 | 日次作業 | 週次作業 | 月次作業 | 学期初め |
|------|---------|---------|---------|---------|

| **HR担任**（30名） | 2分（声かけ+結果確認） | 5分（要注意生徒チェック） | 10分（月次レポート確認） | なし |
| **学年主任**（3名） | なし | なし | 15分（学年レポート確認） | なし |
| **その他教員**（22名） | なし | なし | なし | なし |

**出題はシステムが完全自動で行うため、日常的な出題操作は不要。** 教科主任が学期初めに10分程度で配信スケジュール（曜日パターン + 休止期間）を設定すれば、以降は自動運用される。従来の出題担当6名の役割は不要になり、教科主任2名による最小限の管理のみで運用可能。
